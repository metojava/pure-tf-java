Optimizers

After loss.backward() fills each parameter's gradient (p.grad), an optimizer decides how to update p.data. All optimizers implement the Optim.Stepper interface: 

public interface Stepper {
    void setLr(float lr);       // called each epoch by the schedule
    void step(List<Tensor> params);
}

Available optimizers in Optim

OptimizerConstructorIdea
SGDOptim.sgd(params, lr) Plain: p -= lr * grad. Updated outside a Stepper.
Momentumnew Optim.Momentum(lr, momentum) Accumulates a velocity to smooth updates and escape local minima.
RMSPropnew Optim.RMSProp(lr [, decay, eps]) Normalizes each weight's step by an running average of its squared gradient.
Adamnew Optim.Adam(lr [, beta1, beta2, eps]) Combines momentum + RMSProp with bias correction. Default choice.

Using them

// Classic Adam (most reliable for Fashion-MNIST):
Sequential net = new Sequential()
        .add(new Flatten())
        .add(new Dense(128, Dense.Act.RELU))
        .add(new Dense(10));

History h = net.fitHistory(trI.pixels(), trL.labels(), 10,
        5, 128,
        new Optim.Adam(0.0015f),
        LrSchedule.cosine(0.0015f, 0.0002f, 5),
        0f, null, true);

// Momentum or RMSProp swap in with one line:
// new Optim.Momentum(0.01f, 0.9f)
// new Optim.RMSProp(0.001f)

Learning-rate schedules

LrSchedule is a functional interface returning the LR for each epoch. 

@FunctionalInterface
public interface LrSchedule {
    float lrAt(int epoch);
    static LrSchedule constant(float lr);
    static LrSchedule step(float lr, int dropEvery);      // halve every N epochs
    static LrSchedule cosine(float maxLr, float minLr, int totalEpochs);
    static LrSchedule exponential(float lr, float decay);
}
LrSchedule.constant(0.001f);                 // always 0.001
LrSchedule.step(0.01f, 3);                    // 0.01, then 0.005, ...
LrSchedule.exponential(0.01f, 0.7f);          // 0.01 * 0.7^epoch
LrSchedule.cosine(0.005f, 0.0007f, 5);        // cosine anneal
// Or write any custom schedule as a lambda:
LrSchedule custom = epoch -> 0.001f / (1 + epoch);

What cosine annealing does

Cosine annealing decays the LR along a cosine curve from maxLr down to minLr across the epochs: 

lr(epoch) = minLr + 0.5 * (maxLr - minLr) * (1 + cos(pi * epoch / (totalEpochs - 1)))
  • Early: near maxLr — big steps, fast initial progress.
  • Middle: the step size decays smoothly.
  • End: near minLr — tiny steps so the optimizer settles cleanly instead of overshooting the optimum.

Measured effect (from our experiments)

On the current MLP + dropout model, we swept the LR and the schedule and recorded the results (12k-subset, 3 epochs, batch 128). Speed was identical for every config — the optimizer does not change the number of floating-point operations. Only the accuracy and loss moved.
