The training loop, in one picture

Training is a repeated cycle: for each epoch, shuffle the data, slice it into batches, and for each batch do forward → loss → backward → optimizer.step. Everything here is handled by Sequential, but it helps to see it. 

for (int epoch = 0; epoch < epochs; epoch++) {
    opt.setLr(sched.lrAt(epoch));          // learning-rate schedule
    net.setTraining(true);
    shuffle(idx, new Random(1000L + epoch));  // per-epoch shuffling

    for (int start = 0; start < nTr; start += batch) {
        Tensor.resetGraph();               // new tape for this batch
        Tensor logits  = net.forward(batchX);
        Tensor loss    = Tensor.softmaxCE(logits, batchLabels);
        for (Tensor p : net.params()) p.zeroGrad();
        loss.backward();                   // fills every p.grad
        opt.step(net.params());            // update weights
    }
}

High-level methods on Sequential

In practice you call one of these:

MethodUse
fitClassifier(X, Y, classes, epochs, batch, lr, verbose) Simple classifier training with a fixed LR (returns double[]).
fitClassifier(...) overload Same name returning a History.
fitHistory(X, Y, classes, epochs, batch, opt, sched, valSplit, earlyStop, verbose) Full control: any optimizer, any LR schedule, optional validation and early stopping. Returns History.
evaluate(X, Y, classes) Returns double[]{loss, accuracy} on any set.
predict(X)Raw logits float[n][classes].
predictClass(X)Argmax class id per sample.

The recommended call: fitHistory

It gives you the most control and returns a History you can plot or summarize. Signature: 

public History fitHistory(float[][] X, int[] Y, int classes,
                          int epochs, int batch,
                          Optim.Stepper opt, LrSchedule sched,
                          float valSplit, EarlyStopping earlyStop,
                          boolean verbose)
History hist = net.fitHistory(trainX, trainY, 10,
        5, 128,
        new Optim.Adam(0.005f),
        LrSchedule.cosine(0.005f, 0.0007f, 5),
        0.1f,                 // hold back 10% for validation
        null,                 // no early stopping
        true);                // print per-epoch loss/acc/time

hist.printSummary();

The Dataset helper

puretf.data.Dataset wraps your feature rows and labels and handles the bookkeeping every workflow needs: shuffling, train/val splits, mini-batches, and quick subsets — all keeping features and labels aligned. 

import puretf.data.Dataset;

Dataset ds  = new Dataset(trainX, trainY);      // features float[n][d], labels int[n]
Dataset sub = ds.subsample(12000);              // evenly-spread first 12k (fast tests)
ds.shuffle(733L);                               // seeded shuffle (in place)

Dataset.Split sp = ds.split(0.9);               // train/val split (two views)
Dataset train = sp.train(), val = sp.val();

for (Dataset.Batch b : train.batches(128)) {    // mini-batches of features+labels
    float[][] bx = b.x();                       // float[batch][d]
    int[]     by = b.y();                       // int[batch]
    // ... forward(bx), loss, backward, optimizer.step ...
}

Operations only permute an internal index array, so the raw feature/label arrays are never copied or reordered — splits are views, not copies, and stay cheap.

Input format

  • X is float[n][featureDim] — each sample is one row.
  • Y is int[n] for classifiers (the class id), or float[n][outDim] for the regression fit methods.
  • classes is the number of output classes (for the classifier loss and metrics).

Per-epoch output

With verbose=true you get a real-time line per epoch (this is what the demos print): 

Epoch 1/5 - loss 0.5604 - accuracy 0.7974 (4.6 s)
Epoch 2/5 - loss 0.4203 - accuracy 0.8453 (4.2 s)
Epoch 3/5 - loss 0.3764 - accuracy 0.8620 (4.0 s)
Epoch 4/5 - loss 0.3361 - accuracy 0.8751 (3.8 s)
Epoch 5/5 - loss 0.3172 - accuracy 0.8828 (3.8 s)

Each line shows loss, training accuracy, and the seconds that epoch took. Loss falls monotonically and accuracy climbs — the model is still learning, so more epochs would help.

Batching and epochs

Epoch = one full pass over the whole training set (60 000 images here). Batch = the slice of images (e.g. 128) the weights are updated on at once. A batch size of 128 on 60k images means 469 weight updates per epoch. Smaller batches update more often (noisier but may generalize better); larger batches are smoother and slightly cheaper per image.

Early stopping (optional)

Pass an EarlyStopping to stop once validation stops improving and restore the best weights found: 

EarlyStopping es = new EarlyStopping(5);  // patience = 5 epochs
History hist = net.fitHistory(..., 0.1f, es, true);
