Why recurrent networks?

A Dense layer maps a fixed-size vector to a fixed-size vector. Language is a sequence: a sentence has variable length, and each word's meaning depends on what came before. Recurrent networks consume sequences step by step while carrying a hidden state — a running memory of everything seen so far. In this library all sequence input follows one convention: 

[B, T, D]   =  B sentences (batch), T tokens each (time), D features per token

The engine unrolls each time step through primitive autograd ops, so gradients are exact backpropagation-through-time (BPTT), no approximations.

Meet the family: RNN, LSTM, GRU

LayerRecurrenceTrade-off
RNN h' = tanh(x·K + h·U + b) simplest; suffers vanishing gradients over long sequences
LSTM input/forget/output gates + a separate cell state c the deliverable: long-term memory, standard for text
GRU update/reset gates, no separate cell state cheaper than LSTM, similar accuracy

How the LSTM actually works

Here is the exact computation the library runs in LSTM.step, for one time step (units H). The kernel K, recurrent U and bias b are shaped [D,4H], [H,4H] and [4H], packed as four gate blocks i|f|g|o: 

z   = x·K + h·U + b                    // [B, 4H] combined gate inputs
gi  = sigmoid(z[:H])         // input gate
gf  = sigmoid(z[H:2H])       // forget gate
gg  = tanh(  z[2H:3H])       // candidate cell content
go  = sigmoid(z[3H:4H])      // output gate

c'  = gf * c + gi * gg       // update the cell memory
h'  = go * tanh(c')          // new hidden state
Read it in words. The forget gate decides how much of the old memory c to keep, the input gate how much new candidate content gg to write in, and the output gate how much of the memory to expose as the hidden state h. Because the cell state c is only scaled (never overwritten by a squashing function), it can carry gradients across very long distances — that is precisely why LSTMs beat plain RNNs on language. The library even initializes the forget-gate bias to 1 (a common trick that makes the model start "remembering").

Recurrent layer API

new RNN(units)                          // return last state only
new LSTM(units)                         // return last state only
new GRU(units, true)                    // return EVERY timestep: [B, T, H]

ConstructorOutputUse it for
LSTM(units)[B, H] (last state) sentiment / classification / sequence-to-one
LSTM(units, true)[B, T, H] (every step) sequence-to-sequence, stacked RNNs, tagging
Connecting to a classifier. Dense expects [rows, features]. With returnSequence=false the LSTM already gives [B,H], so a Dense follows directly. With returnSequence=true you get [B,T,H] and must reshape to [B*T, H] before a Dense (see Chapter 10's text demo).

Text preprocessing: the Tokenizer

Networks eat numbers, not letters. Tokenizer turns raw text into integer token ids and back: 

Tokenizer tok = new Tokenizer(corpus);     // learns every character's id
int   vocab = tok.size();                   // rows for the Embedding table
int[] ids   = tok.encode("to be");          // [t, o, ' ', b, e] -> int ids
String s    = tok.decode(ids);              // back to "to be"

It is character-level by default — which is enough to build language models and still captures spelling. For word-level models, pre-tokenize your corpus yourself and call encodeTokens(String[]). Longer sequences should also be padded/truncated to a fixed T for batching (see the notes at the end).

NLP models you can build — and how

1 · Language model / text generation

The task: given the words so far, predict the next token. Trained by teacher forcing — feed the real sequence, ask for each next char (returnSequence=true). Then generate by feeding the growing prefix and sampling. This is exactly run.cmd lstm-text. 

Sequential body = new Sequential()
        .add(new Embedding(vocab, embedDim))
        .add(new LSTM(lstm, true));               // [B,T,H] per timestep
Sequential head = new Sequential().add(new Dense(vocab));

// train one sequence, teacher-forced:
Tensor bodyOut = body.forward(Tensor.of(floats(data), 1, T));  // [1,T,H]
Tensor logits  = head.forward(bodyOut.reshape(T, lstm));       // [T,vocab]
Tensor loss    = Tensor.softmaxCE(logits, target);             // next-char labels
// ... zeroGrad, backward, clipGradNorm, Adam.step ...
// generate:
int next = Sampler.categorical(rnd, lastLogits, 0.8f);   // temperature sampling
String s = tok.decode(new int[]{next});

Small temperature → predictable text; high temperature → creative/random.

2 · Sentiment / text classification

Sequence-to-one: run the LSTM over the sentence and classify the final hidden state. Because we only need the last state, use LSTM(units, false) and a Dense(classes) head. 

Sequential classifier = new Sequential()
        .add(new Embedding(vocab, embedDim))
        .add(new LSTM(64))                       // -> [B, 64]
        .add(new Dense(2));                      // positive / negative
classifier.fitClassifier(...);                   // reuse Chapters 4 & 6 machinery

With returnSequence=false, the model is a drop-in for every classifier API you already know in Chapters 4–6 (fit, evaluate, Metrics, predict).

3 · Sequence-to-sequence (translation, summarisation, chatbot)

Encoder–decoder: an encoder LSTM reads the source and returns every state; a decoder LSTM reads those plus the target, so it can emit one output per target step. This is the architecture behind translation without attention. 

Sequential encoder = new Sequential()
        .add(new Embedding(srcVocab, embedDim))
        .add(new LSTM(hidden, true));            // [B, T, H] for the decoder
Sequential decoder = new Sequential()
        .add(new Embedding(tgtVocab, embedDim))
        .add(new LSTM(hidden, true));            // emit every target step
// head: reshape [B,T,H] -> [B*T,H], Dense(tgtVocab), softmaxCE against target text

4 · Time-series forecasting & regression

Sequences need not be words. Feed a window of past sensor readings / prices as [B, T, D] and train an LSTM to predict the next values (a regression, so use mse): 

Sequential forecaster = new Sequential()
        .add(new LSTM(32))                        // last state
        .add(new Dense(4, Dense.Act.RELU))
        .add(new Dense(1));                       // predicted next value
Tensor loss = pred.mse(target);                   // mean squared error
loss.backward(); net.clipGradNorm(1f); opt.step(net.params());

5 · Tagging & autocomplete

Part-of-speech tagging, named-entity recognition, or next-word autocomplete all want an output per token — so returnSequence=true plus a Dense head (per-token labels), as in the language-model pattern above.

Complete worked example (draft)

A ready-to-adapt skeleton combining everything. This character language model is the LstmTextDemo in miniature — copy it and swap the corpus for your own text. 

import puretf.Optim;
import puretf.Tensor;
import puretf.data.Sampler;
import puretf.data.Tokenizer;
import puretf.nn.*;

public final class TinyCharLM {
  public static void main(String[] a) {
    String text = "java is pure fun. java is pure fun. java is pure fun. ";
    Tokenizer tok = new Tokenizer(text);
    int V = tok.size(), T = text.length();
    int[] data = tok.encode(text), target = new int[T];
    for (int i = 0; i < T - 1; i++) target[i] = data[i + 1];
    target[T - 1] = data[0];

    Sequential body = new Sequential()
        .add(new Embedding(V, 24)).add(new LSTM(48, true));   // [1,T,48]
    Sequential head = new Sequential().add(new Dense(V));
    body.build(T); head.build(48);
    var params = new java.util.ArrayList<Tensor>();
    params.addAll(body.params()); params.addAll(head.params());
    Optim.Adam adam = new Optim.Adam(0.004f);

    for (int s = 0; s < 200; s++) {
      Tensor.resetGraph();
      Tensor o = body.forward(Tensor.of(f(data), 1, T));       // [1,T,48]
      Tensor lg = head.forward(o.reshape(T, 48));              // [T,V]
      Tensor loss = Tensor.softmaxCE(lg, target);              // scalar
      for (Tensor p : params) p.zeroGrad();
      loss.backward(); body.clipGradNorm(1f); head.clipGradNorm(1f);
      adam.step(params);
      if (s % 50 == 0) System.out.printf("step %d loss %.4f%n", s, loss.data[0]);
    }

    // generate from a seed
    StringBuilder out = new StringBuilder("java ");
    int[] ids = tok.encode(out.toString());
    for (int i = 0; i < 40; i++) {
      Tensor.resetGraph();
      Tensor o = body.forward(Tensor.of(f(ids), 1, ids.length));
      float[] row = new float[48];
      System.arraycopy(o.data, (ids.length - 1) * 48, row, 0, 48);
      int next = Sampler.categorical(new java.util.Random(1), head.forward(
              Tensor.of(row, 1, 48)).data, 0.7f);
      out.append(tok.token(next));
      int[] ids2 = new int[ids.length + 1];
      System.arraycopy(ids, 0, ids2, 0, ids.length); ids2[ids.length] = next; ids = ids2;
    }
    System.out.println(out);
  }
  static float[] f(int[] a){ float[] x=new float[a.length]; for(int i=0;i<a.length;i++) x[i]=a[i]; return x; }
}

Practical gotchas

  • Clip your gradients. Call net.clipGradNorm(1f) after backward(); recurrent nets love to explode.
  • Keep sequences short for speed. Cost grows with T (every step is a matmul). A few hundred tokens is fine on CPU.
  • Pad/truncate for batching. To train many sentences at once, pad them to a common T; for now the demos train one sequence at a time.
  • Match the head reshape. [B,T,H] → [B*T,H] before Dense; sample only the latest row during generation.
