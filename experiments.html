Fashion-MNIST MLP — Optimizer / LR Experiments

All runs use the pure-Java autograd engine on an 8-core CPU. See "Project & model under test" below for the architecture, project and dataset.

Headline finding: learning rate and schedule change accuracy and loss but have essentially no effect on speed — every config does the same number of floating-point operations per epoch. Speed is fixed by the architecture and dataset size.

Project & model under test

This document describes experiments we ran in the pure-tf-java project (C:\Users\dell\Desktop\b\pure-tf-java) — a from-scratch, pure-Java autograd engine with no TensorFlow and no JFreeChart (visualization is plain Java2D). The entry point is puretf.demo.CnnFashionMnistDemo (kept its historical "Cnn" name — it currently runs an MLP, the CNN was commented out).

Architecture (batch size 128, Adam optimizer):

Flatten                     // 28x28 image -> 784 features
   -> Dense(128, relu)
   -> Dropout(0.2)
   -> Dense(64, relu)
   -> Dense(10)             // 10 logits (classes)

Dataset: Fashion-MNIST — 60 000 train / 10 000 test, 28×28 grayscale images in 10 classes (T-shirt, Trouser, Pullover, Dress, Coat, Sandal, Shirt, Sneaker, Bag, Ankle boot).

What "cosine" (cosine annealing) does

The LR schedule is LrSchedule.cosine(maxLr, minLr, totalEpochs) in puretf.nn.LrSchedule.java. It decays the learning rate along a cosine curve over the epochs:

lr(epoch) = minLr + 0.5 * (maxLr - minLr) * (1 + cos(pi * epoch / (totalEpochs - 1)))
  • Start (early epochs): near maxLr — big weight updates, so the net makes fast initial progress.
  • Middle: the step size decays smoothly.
  • End (final epoch): near minLr — tiny updates, so the optimizer "settles" cleanly into a good minimum instead of overshooting.

Why it helps Fashion-MNIST here: it combines fast early convergence with a fine final settling, which is why cosine beat a constant LR (85.15% vs 81.85% test accuracy on the subset). Conceptually it trades off the same way in any dataset with a smooth, non-convex loss landscape — start big, anneal small.

How to reproduce

cd C:\Users\dell\Desktop\b\pure-tf-java
mvn -q compile exec:java -Dexec.mainClass=puretf.demo.CnnFashionMnistDemo \
    --lr=0.005 --schedule=cosine 5

Flags supported by the demo: <epochs> (default 5), --fast (12k/2k subset), --nochart (no GUI window), --lr=<value>, --schedule=cosine|constant|step|exponential. Each run prints a RESULT line for easy aggregation.

Conclusion

  • Best setting found: LR = 0.005 with cosine schedule.
  • Accuracy improves with the higher LR (85.35% vs 80.25% on the subset; 87.48% on full 60k).
  • Speed is unchanged by the optimizer — it's driven purely by architecture + data size.
